# 唐山教考 2026

唐山工业职业技术大学 2026 年公开选聘（教育类岗位）**笔试备考资料**。

> 笔试：2026-09-27 · 120 分钟 / 100 分 · 教育专业能力测验 + 公共基础知识**合并一张卷** · 全客观题
> 面试：试讲 + 答辩，占总成绩 **60%**（笔试只占 40%）

这不是一套现成的复习资料汇编，是**自己搭的备考系统**：一份能点的考点体系网页、一个 1000 道题的可刷题库，外加出题蓝图和配套工具。

## 怎么用

```bash
python3 server.py            # 起服务，默认 8000 端口，只依赖标准库
```

然后浏览器打开 <http://127.0.0.1:8000/>（就是 `web/index.html`）。**不联网也能用**——字体走 Google Fonts，断网只是降级成系统字体，页面照常。

手机上看：连**同一个 WiFi**，打开启动时打印的那个局域网地址（`http://<本机 IP>:8000`）。

页面顶部的导航栏切换分类，键盘 `←` `→` 前后翻。刷题页 1000 题分页渲染，首屏 40 题、逐页往下加载。

数据分两处存：**做题记录、错题本、模考存档的真相在服务端 `bank.db`**；刷题页同时在本机 localStorage 存一份镜像（`jiaokao-answers-2026` / `jiaokao-wrong-2026`），所以页面在服务没起来时会读不到题（数据还在，服务一起来就恢复）。换设备只要连的是同一个服务，记录就跟着走。

> 旧版单文件页 `考点体系.html` 还在（保留作回归对照），但它**不再更新**，数据也和 `bank.db` 不同步——别拿它当题库用。

### 题目格式

```json
{
  "id": "e101",
  "n": 1,
  "module": "教育学",
  "section": "edu",
  "type": "single",
  "stem": "题干",
  "options": [{"key": "A", "text": "…"}, {"key": "B", "text": "…"},
              {"key": "C", "text": "…"}, {"key": "D", "text": "…"}],
  "answer": "B",
  "explanation": "解析",
  "batch": 1
}
```

`judge` 的 `options` 恰好 2 项（「正确」「错误」），`multi` 的 `answer` 是 ≥2 个**升序**字母（如 `"ABD"`）。字段规范与校验规则见 `出题范围.md` 第四节。

> ⚠️ 唯一的人工痕迹是 `n` 的补零：**id 没有统一补零**——第一批是 `e1`–`e9`，之后是 `e101`、`e201` 这样的三段式。**id 一旦发出不复用**（错题本按 id 记，复用会串）。

## 已知局限（重要）

1. **答案未经人工复核。** 1000 题里大部分是按考点生成的，只做了**格式与范围校验，没有逐题核对答案**。刷题时觉得答案别扭，**以教材和法条原文为准，别信题库**。

2. **有时效性的题，考前需要重新确认**，例如：
   - 治安管理处罚法 2025 年修订，2026-01-01 施行
   - 引用《事业单位工作人员处分暂行规定》的题目——该规定已于 2023-09-01 被人社部令第 52 号替代
   - 时政题答案会随新闻变，考前一周重新扫一遍

3. **时政覆盖很薄**（政治与时政模块里时政仅 5 道）。笔试时政通常考考前 3–6 个月，题库覆盖不到那么新，需要另外看新闻。

4. **模考成绩会并进刷题记录**，考完「已做」+120、正确率会变。这是故意的，不想被影响就去刷题区点「清空记录」。

5. **模考页的「练兵版」开关现在不会出现。** 它本来是用来「掺入判断题 / 多选题」的，但这个开关**只在题库里真有判断/多选时才渲染**——当前 1000 题全是单选，渲染它就成了承诺卷子里没有的题型。题库哪天进了这两类题，开关自己回来。

6. **「导入旧版记录」是只补不盖的，有些信息回不来。** 首页那个按钮把旧页面 localStorage 里的作答 / 错题一次性并进 `bank.db`：
   - 导进来的 `wrong_count` **一律是 1**——旧数据里没有「错次」这个概念，不可恢复，不是 bug；
   - 服务器上**已经知道**的题（有作答行或错题行）**一个字都不动**，连它的错题也不补。旧记录可能比服务器上的更旧，拿它去盖会把「答对」翻成「答错」、正确率拉下来；
   - 靠一个 `jiaokao-migrated-2026` 标记防重复：同一份数据重导不会多出行，也不会把错次累加成 2。

7. **错题本里「标记已订正」只能点一次。** 点完那一行就从错题本消失（库里的行留着、`resolved=1`）。想再看它，只能重新做那道题。这是接受的代价。

8. **冲刺表（`sprint.html`）本阶段仍存浏览器 localStorage，`bank.db` 里的 `sprint` 表是空的。** 有意的取舍：冲刺勾选是纯本机的进度标记，没进服务端。换设备 / 换浏览器，**冲刺进度不跟着走**（作答与错题本跟着走，见上面第 6 条）。

9. **没有测试检查生成页的 `<script src>` 指不指得到真文件。** `web/*.html` 里引的 `assets/*.js` 只是路径字符串，拆页脚本和现有测试都不解析它——`web/wrong.html` 曾经 404 一个 `assets/wrong.js` 很久，而全部测试都是绿的（T15 才发现）。改页面脚本引用时自己确认一遍 `web/assets/` 下有那个文件。**这是已知的测试盲区，尚未补测试。**

## 架构改造（已完成）

改造把 56.6 万字符的单文件拆成了「SQLite + 拆页 + 服务」：题目进 `bank.db`，页面拆到 `web/`，数据由 `server.py` 供。设计见 `docs/题库架构改造-design.md`。四步里前三步已落地：

1. **数据层** —— 已做：题库进 SQLite，字段含题型、分类、来源
2. **拆页 + 服务** —— 已做：14 个内容页 + 总览 + 错题本，`server.py` 供数
3. **题型扩展 + 错题本页** —— 已做：judge / multi 引擎、错题本独立成页、模考练兵版开关
4. **扩充 1000 题**（题库到 2000，真正掺入判断 / 多选）—— **未做**，另出计划

旧版 `考点体系.html` 在四步全部收尾前一直留着作回归对照（`tests/test_split.py` 拿它逐字节比对生成页）。第 4 步完成、schema 与 `grade()` 冻住之后，它才可以删。
